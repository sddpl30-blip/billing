# Audit, October 2026

An audit of security, billing arithmetic, the frontend and deployment, and the
fixes that followed. Where this disagrees with `RELEASE-CANDIDATE.md` or
`PRODUCTION-READINESS.md`, this is the newer one.

## How it was checked

Every suite runs green against PostgreSQL 16 on a freshly migrated database:
typecheck, the Vite build, the engine (77 + 66 + 34 checks), the database and
domain schema checks, the Postgres client, documents, security, SMTP, wiring,
deploy, serverless, the full API suite over both the socket and the serverless
transport (223 checks each), and both Playwright suites (36 + 23). The merged
app was also driven in Chromium in server mode, at 1280px and 375px, as
resident, manager and committee: billing run, approve, release, convert,
manager receipt, receipt and invoice PDFs, and a two-role account switching
views. `.github/workflows/ci.yml` runs all of it, plus both Docker builds, on
every push.

## Fixed

### Security
- Wrong one-time codes were never counted: the counter was written inside the
  transaction the refusal rolled back. A 6-digit code could be guessed without
  limit. Counted outside it now, with a per-address bucket as well.
- A manager could schedule a due-date conversion job and so issue tax invoices
  without the treasurer. A job now needs the permission its work needs.
- One account could enter and approve its own rate or GST setting. The
  proposer is recorded and the database refuses an approval by them
  (migration 008); nobody may change their own roles or hold secretary with
  treasurer.
- Rate limits read the client-supplied end of `X-Forwarded-For`; behind nginx
  with no `TRUST_PROXY`, ten bad logins locked out the whole society.
- Production returned 500 for a known address and 200 for an unknown one on
  code requests, which enumerated members.
- Residents could write new "official" copies of their invoices; cross-site
  sign-in posts were accepted (login CSRF); `/api/health` returned database
  error text unauthenticated; job keys were global across societies; remote
  database connections defaulted to `sslmode=prefer`.

### Billing and accounting
- "Jul  2026" and "Jul 2026" were different periods, so a month could be
  billed twice (migration 007 canonicalises and enforces it).
- A cancelled invoice could never be re-billed.
- A payment against a proforma went to advance and was never applied.
- Cancelling a part-paid invoice left a negative receivable.
- The ₹7,500 per-member GST threshold was never applied.
- Reports defaulted to a `from` after `to` from January to March.
- Tax invoice numbers restarted each January rather than each April.
- "Today" was the UTC date, a day behind from midnight to 05:30 IST.
- TDS was taken on the bill including GST, and the two engines rounded it
  differently; festival collections and imported late interest were booked to
  the wrong heads; concurrent receipts and uncapped credit notes could
  over-allocate; CGST and SGST could differ by a paisa.

### Frontend
- The built app crashed to a blank screen once invoices loaded.
- In server mode every document action failed (the snapshot carried no ids),
  writes reported invented results before the server answered, errors were
  swallowed, fund balances and charts were hard-coded, demo-only actions ran
  against the server, and a manager had no way to record a receipt.
- A missing server in a production build silently showed the sample society.
  Production builds now require the server; a static demo must be built with
  `VITE_DATA_SOURCE=demo`.
- Theme tokens throughout, accessible dialogs and toasts, readable gold, and
  the bundle split from one 908 kB chunk into app 280 kB, React 224 kB and
  charts 388 kB (charts only load for the dashboards).

### Deployment
- The Vercel function could not load (ESM with extensionless imports); it now
  imports the compiled server, and a test loads it the way Node does.
- The Docker backend image could not build, and its migrate step crashed.
  Fixed from reading the files; no Docker daemon was available to build it
  here, so the CI docker job is the first real build. Check it goes green.
- The systemd unit killed Node at startup (`MemoryDenyWriteExecute`).
- Production had no way to deliver a sign-in code. `OTP_PROVIDER=email` sends
  it through SMTP.
- A nightly `pg_dump` timer for the VPS; CI; complete env templates.

## Decisions for the society

- **GST threshold.** The ₹7,500 test compares the bill's taxable maintenance
  and leaves the sinking fund out. Have the CA confirm that reading, and the
  society's turnover position, before billing GST at all.
- **Hosting.** Vercel Hobby is for non-commercial use; check that fits.

## Still open

- Screens for what the API already supports: vendor master and bills, bank
  import and reconciliation, settings/rate/GST approval, period close and
  reopen, ticket assignment, credit and debit notes, users and roles, and the
  server-side reports (ageing, GST, TDS, statements, the statutory set).
- No SMS provider, payment gateway, bank API or GSTN/TRACES filing (see the
  README's "What is still not connected").
- Late-payment penalties are not computed; imported ones are booked correctly.
- Alerting on failed jobs and a log drain beyond the platform's retention.
- HTTPS on the VPS needs certbot run once (`deploy/nginx-site.conf`).
